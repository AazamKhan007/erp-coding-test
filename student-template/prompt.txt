  apiEndpoint?: string;
  suppliers?: Supplier[];
  refreshIntervalMs?: number;
  theme?: "light" | "dark";
  viewMode?: "cards" | "table";
  className?: string;
};

The props should work as follows:

- apiEndpoint:
  Optional URL used to fetch supplier performance data.
- suppliers:
  Optional supplier data provided directly by the parent component.
- refreshIntervalMs:
  Optional refresh interval in milliseconds. If provided, the component should periodically refresh data from the API.
- theme:
  Optional theme value. Supported values are "light" and "dark". Use "light" as the default.
- viewMode:
  Determines whether the widget is displayed as cards or a table. Supported values are "cards" and "table". Use "cards" as the default.
- className:
  Optional CSS class name for customizing the widget container.

STATUS AND COLOR-CODING LOGIC

Calculate the supplier status using the following rules:

- Green:
  onTimeDeliveryPct is greater than or equal to 95 AND avgResponseTimeHours is less than or equal to 4.

- Yellow:
  onTimeDeliveryPct is greater than or equal to 85 AND avgResponseTimeHours is less than or equal to 8, but the supplier does not meet the Green criteria.

- Red:
  Any supplier that does not meet the Green or Yellow criteria.

Implement the status calculation in a reusable helper function, for example:

function getSupplierStatus(
  onTimeDeliveryPct: number,
  avgResponseTimeHours: number
): "Green" | "Yellow" | "Red"

Use the following color mapping:

- Green:
  Background: light green
  Text: dark green
  Indicator: #16a34a

- Yellow:
  Background: light yellow
  Text: dark yellow or dark orange
  Indicator: #ca8a04

- Red:
  Background: light red
  Text: dark red
  Indicator: #dc2626

The status should be calculated from the performance values. If a supplier has a status property, allow it to override the calculated status only when explicitly configured.
